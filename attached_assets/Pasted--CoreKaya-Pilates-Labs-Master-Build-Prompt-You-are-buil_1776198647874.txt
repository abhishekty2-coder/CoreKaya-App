# CoreKaya Pilates Labs — Master Build Prompt

You are building **CoreKaya Pilates Labs**, a premium mobile-first React + Express app for Pilates equipment owners. The existing codebase is a React frontend (Vite + Tailwind + shadcn/ui) with a Node/Express API backend using Drizzle ORM on PostgreSQL, with Gemini AI integration. The current app has four tabs: Weekly Drop (home), The Labs (workout library), Shop (equipment store), and AI Coach. The session-based user system tracks streak, favorites, wishlist, and completed workouts.

Everything below is an instruction. Build it exactly as described. Do not ask for clarification. Do not skip sections. Apply everything in sequence.

## SECTION 1 — DATABASE SCHEMA ADDITIONS

Add the following new tables to `lib/db/src/schema/`. Create a new file `lib/db/src/schema/gamification.ts` and add all of these:

**Table: `user_xp`**
Fields: `id` (serial PK), `session_id` (text, not null), `total_xp` (integer, default 0), `level` (integer, default 1), `updated_at` (timestamp with timezone, auto-update).

**Table: `badges`**
Fields: `id` (serial PK), `slug` (text, unique, not null), `name` (text, not null), `description` (text, not null), `icon_emoji` (text, not null), `xp_reward` (integer, default 0), `unlock_condition_type` (text, not null — values: `streak`, `workouts_completed`, `category_count`, `first_workout`), `unlock_condition_value` (integer, not null).

**Table: `user_badges`**
Fields: `id` (serial PK), `session_id` (text, not null), `badge_id` (integer, references badges.id), `earned_at` (timestamp with timezone, default now).

**Table: `user_body_checkins`**
Fields: `id` (serial PK), `session_id` (text, not null), `workout_id` (integer, not null), `feeling` (text, not null — values: `easy`, `good`, `tough`), `checked_in_at` (timestamp with timezone, default now).

**Table: `user_onboarding`**
Fields: `id` (serial PK), `session_id` (text, unique, not null), `goal` (text), `experience_level` (text), `equipment_owned` (text array, default empty), `days_per_week` (integer), `is_complete` (boolean, default false), `completed_at` (timestamp with timezone).

**Table: `streak_shields`**
Fields: `id` (serial PK), `session_id` (text, not null), `shields_available` (integer, default 1), `last_earned_at` (timestamp with timezone), `updated_at` (timestamp with timezone, auto-update).

Export all of these from `lib/db/src/schema/index.ts`.

Run the migration to apply these tables to the database.

Seed the `badges` table with exactly these rows on startup if empty:

| three-day-flame | Three Day Flame | Maintained a 3-day streak | ⚡ | 75 | streak | 3 |
| week-warrior | Week Warrior | Completed a full 7-day streak | 🏆 | 150 | streak | 7 |
| reformer-initiate | Reformer Initiate | Completed 3 Reformer Lab workouts | 🛠️ | 100 | category_count | 3 |
| mat-master | Mat Master | Completed 10 Mat Lab workouts | 🧘 | 200 | category_count | 10 |
| century | Century | Completed 100 total workouts | 💎 | 500 | workouts_completed | 100 |
| consistent-ten | Consistent Ten | Completed 10 total workouts | ⭐ | 100 | workouts_completed | 10 |

## SECTION 2 — API ROUTES ADDITIONS

### 2a. XP and Badge Engine — `artifacts/api-server/src/routes/gamification.ts`

Create this new route file. Export a router and register it in `src/routes/index.ts`.

**`GET /gamification/status`**
Reads `x-session-id` header. Returns the user's current XP total, level name, XP needed for next level, all badges that exist, and which badges the user has already earned (with `earned_at`). Level thresholds: Level 1 = 0 XP, Level 2 = 200 XP, Level 3 = 500 XP, Level 4 = 1000 XP, Level 5 = 2000 XP. Level names: Beginner, Practitioner, Devotee, Expert, CoreKaya Master.

**`POST /gamification/award-xp`**
Body: `{ amount: number, reason: string }`. Reads session id. Adds XP to `user_xp` table, recalculates level, returns updated totals. If the user levels up, include `leveledUp: true` and `newLevel` in the response.

**Badge check function** — after every call to `POST /user/progress` (workout completion), run a badge eligibility check inside the same transaction. Check all badge conditions against the user's current stats. For any badge whose condition is now met and which the user has not yet earned, insert into `user_badges` and call `POST /gamification/award-xp` internally with that badge's `xp_reward`. Also award 10 XP baseline for any workout completion. Return a `newBadges` array in the workout completion response containing any newly earned badge objects.

**`GET /gamification/badges`**
Returns all badges with a boolean `earned` field and `earned_at` for those earned by this session.

### 2b. Body Check-in Route — add to `artifacts/api-server/src/routes/user.ts`

**`POST /user/checkin`**
Body: `{ workoutId: number, feeling: 'easy' | 'good' | 'tough' }`. Inserts into `user_body_checkins`. Returns the inserted row.

**`GET /user/checkin-history`**
Returns last 20 check-ins for the session, joined with workout title.

### 2c. Onboarding Route — add to `artifacts/api-server/src/routes/user.ts`

**`GET /user/onboarding`**
Returns the onboarding record for the session, or `{ isComplete: false }` if none exists.

**`POST /user/onboarding`**
Body: `{ goal, experienceLevel, equipmentOwned, daysPerWeek }`. Upserts into `user_onboarding`, marks `is_complete: true`. Returns the full record.

### 2d. Streak Shield Route — add to `artifacts/api-server/src/routes/user.ts`

**`POST /user/streak-shield`**
When called, if the user's `shields_available > 0` in `streak_shields`, set `shields_available -= 1` and prevent the streak from resetting to zero on the current day by setting `last_workout_date` to today in `user_state`. Return `{ used: true, shieldsRemaining: number }`.

### 2e. Workout Completion — update existing `POST /user/progress`

Modify the existing response from `POST /user/progress` to also return:
- `newBadges: BadgeObject[]` — any badges just earned
- `xpEarned: number` — XP awarded for this completion
- `newLevel: string | null` — if they leveled up, the new level name, else null
- `totalXp: number` — their updated total XP
